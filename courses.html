用 Gemini 做音乐可视化

核心思路：学员不写代码——用自然语言对 Gemini 描述，让它生成可运行的 HTML／JavaScript， 自己负责迭代提示词与审美。载入自创或获授权的音乐，让画面真正随声音反应 （低/中/高频 + 节拍），再打磨为有笔触和留白的水墨，最后分享可运行链接。

当天产出 — 可在浏览器打开的交互作品 + 课堂同学可访问的链接 + 30 秒 演示视频 + 提示词日志（≥5 轮迭代）
⚠️ 课前确认 3 件事（教师与同学共同检查）
① 音频有使用权吗? 每位同学备一段自己创作或获授权的音频，并准备一段安静与高潮对比明显的片段。
② Google AI Studio 能登录吗? 课前用教室网络打开并完成登录，保存一份正在运行的项目 ZIP 作为回滚点。
③ 本地服务器起了吗? 麦克风和摄像头权限需要 localhost 或 HTTPS；用 python3 -m http.server 在桌面浏览器打开示例，不要从 file:// 打开。
学习目标
  • 掌握生成式 UI 编程范式：描述 → 预览 → 迭代
  • 让画面随音乐多频段反应（低/中/高 + 节拍），做出炫酷效果
  • 把「水墨」做成真水墨：渗墨 · 飞白 · 留白 · 泼墨
  • 设计一种「招牌交互」；理解并调试 AI 生成的代码

无障碍与安全（请先阅读）

本课默认有闪光、抖动、强对比脉冲——对光敏性癫痫是真实风险。下列约束全程适用并计入评分，下表要求可直接复制到提示词中。

防闪光任何闪光都必须少于每秒 3 次，不使用全屏纯白频闪；闪光仅出现在局部，并保持短暂。
减弱动效遵循 @media (prefers-reduced-motion: reduce)：关闭画面抖动与强泛光，将脉冲弱化为透明度渐变。
可暂停／静音始终显示「暂停」和「静音」控件；禁止自动播放有声内容。
对比度确保文字与红色印章在 #FAF6F0 宣纸底色上的对比度达到 WCAG AA 标准。
字幕／声明演示视频加一行字幕；投屏前口头提示「含闪光与运动」。

讲座＋演示 · 用语言「画」出网页
09:00–09:25 · 约 25 分钟 · 教师演示
  1. 生成式 UI 是什么 — 「你不写代码，你描述；Gemini 写出可运行的 HTML。」
  2. 现场一条提示词（约 5 分钟） — 在 AI Studio Build 生成「音频反应的水墨泼墨 + 辉光粒子」页面，当场加载音频——低音一来，墨点炸开。
  3. 报错 = 沟通失败 — 故意触发一个错误，把报错原样粘回 Gemini 让它自己修。
  4. 抛出今日任务 — 用自己的音乐做一张可分享的声音驱动水墨交互页面。
拆解法 · 一步一步来

不要一次让 AI 把整个页面做出来。把大目标拆成一串「单一目的」的小步骤——一次只加一件事，加完就验证，能跑再加下一步。下面这把「拆解阶梯」就是今天五个练习的主线，照着走，不会乱。

拆解阶梯
骨架 → 反应 → 风格：先让它动，再让它「听」，最后才让它「美」。
  1. 搭骨架 — 一个 HTML 文件：全屏 canvas + 渲染循环 + 暂停/静音按钮。验证： 空白画布在持续刷新。 → 练习 1
  2. 进声音 — 载入并能播放/暂停一段本地 .mp3。验证: 能播、能停。 → 练习 2
  3. 取一个数 — 接 FFT，先只把低频一个数字打在屏幕上。验证: 出声时数字在跳。 → 练习 2
  4. 一个映射 — 让那一个数字驱动一个视觉（一个圆随低音缩放）。验证: 鼓点一来圆就涨。 → 练习 2
  5. 逐段添加 — 中频→涟漪，高频→粒子；一次只加一段，加完再加下一段。验证: 每段单独确认对了再继续。 → 练习 2
  6. 加节拍 — 检测重拍 → 闪一下 / 冲击波。验证: 重拍时画面闪一下。 → 练习 2
  7. 平滑处理 — 所有数值做 lerp 平滑。验证: 不再抖，像呼吸。 → 练习 2
  8. 一种交互 — 只选一个「招牌动作」做到爽。验证: 你会想再玩一次。 → 练习 3
  9. 最后添加风格 — 最后才做水墨：渗墨·飞白·留白·印章，让音乐变化真正改变笔触。验证: 像真水墨，不是灰色几何。 → 练习 4
  10. 发布 — 导出 → 分享 → 课堂可访问的链接＋演示视频＋提示词日志。验证: 在另一台桌面电脑打开能跑。 → 练习 5
四条铁律 — ① 先骨架，再血肉，最后皮肤（结构 → 反应 → 风格）。② 一次只改一个变量。③ 加完就验证，能跑再继续。④ 永远留一份「上一版能跑的」项目。
回滚到可用版本并重新描述需求，也是本课要练习的技能。

效果配方＋样例

想更炫？把下面的「配方」一条条加进同一个 Gemini 对话即可（可叠加）。

辉光／泛光
添加一层叠加混合的泛光效果，让明亮部分产生光晕，并向宣纸周围柔和扩散。
节拍粒子
每检测到一次节拍，就发射约 30 个发光墨滴，让它们向外飞散并逐渐淡出。
拖尾
每一帧都不要完全清空画布，而是以约 8% 的强度逐渐擦除，让运动留下丝滑的水墨拖尾。
冲击波
点击或检测到强烈起音时，发出一个向外扩张的圆环，让它经过的画面发生扭曲。
景深／视差
将笔触分成三个景深层次，让各层随鼠标以不同速度移动，形成空间纵深感。
自备素材 — 使用自己创作或获授权的音频；本站的 水墨可视化示例可作为视觉目标与二创参考。没有现成代码也可以从 练习 1 的提示词开始。

练习 1

第一段不写代码的代码

15 分钟

目标 — 感受自然语言 → 可运行 HTML 的瞬间，建立信心。

Google AI Studio Build — 第一条提示词
创建一个单文件 HTML 页面：白色背景，中央放置一个黑色圆形。
点击页面任意位置时，让圆形弹动一次：放大到 1.5 倍后恢复原状。
使用原生 JavaScript，不使用任何库。
整体风格优雅、简洁。
步骤
  1. 打开 Google AI Studio 的 Build 模式，选择网页应用，贴入第一条提示词。
  2. 预览运行，点几下看交互。
  3. 截图 + 存下这一版 HTML。
  4. 自问：你能用一句话描述它在做什么吗？
产出
1 个能跑的 HTML 页面 + 截图。
讨论
  1. 第一次「看到代码运行」是什么感觉？
  2. Gemini 多给了 / 少给了什么？
  3. 这段代码你看得懂吗？需要看得懂吗？
✦
教学点 — 自然语言驱动编程范式下「看不懂代码」不是失败——能描述、能验证才是新技能。
练习 2

让声音住进页面

25 分钟

目标 — 让画面真正「听见」音乐：不是一个圆变大，而是低/中/高三频段 + 节拍各自驱动不同效果。在练习 1 基础上同一对话迭代；报错就粘回 Gemini。

在同一对话中继续迭代
现在加入本地 .mp3 文件加载功能，并提供小型播放／暂停按钮，
通过 Web Audio API 实时驱动画面。将 FFT 分为三个频段，至少让三种视觉元素响应声音：
  - 低频 → 核心图形随每个底鼓节拍脉冲或缩放
  - 中频 → 同心圆环向外形成涟漪
  - 高频 → 发射细小明亮的粒子
加入简单的节拍检测：出现强烈起音时，触发一次短暂闪光或冲击波。
添加柔和的叠加泛光和短暂的运动拖尾，让画面充满活力且不抖动；
用 lerp 对所有数值进行平滑处理，使动态像呼吸一样自然。
使用单文件 HTML、原生 JavaScript 和 canvas。
步骤
  1. 同一对话继续迭代，贴入多频段提示词，加载自己创作或获授权的音频。
  2. 先跑通基础 FFT，再逐条加：低频脉冲 → 中频涟漪 → 高频粒子。
  3. 再加节拍闪光 + 辉光 + 拖尾；所有数值做平滑(lerp)防抖。
  4. 录 30 秒，确认「安静段安静、高潮段炸」；报错粘回 Gemini。
产出
三频段 + 节拍反应、带辉光/拖尾的页面 + 30 秒 录屏（要含一段「安静 → 高潮」对比）。
讨论
  1. 安静段与高潮段的差别够大吗？
  2. 哪个频段最难「听对」？延迟 / 过激 / 麻木怎么调？
  3. Gemini 哪一次给的代码错了？错在哪？
✦
教学点 — 别让一个圆代表整首歌——拆成低/中/高 + 节拍，画面才像在「听」。代码错误 = 沟通失败，粘报错最高效。
练习 3

加一个交互

35 分钟

目标 — 从「被动反应」变「主动可玩」。每人选 1 种作为你的「招牌动作」（宁精勿多），做得够爽。

鼠标「移动鼠标时，让圆形以 0.3 秒的延迟跟随光标。」
键盘「按下空格键时，触发一次短暂的水墨涟漪。」
麦克风「对着麦克风发声时，出现一个较小的圆形，并随我的声音起伏。」
滚轮「向上滚动鼠标滚轮，让色调变暖；向下滚动，让色调变冷。」
摄像头「通过摄像头检测我的脸部左右移动，并让画面随之左右移动。」
拖动画笔「按住鼠标拖动时，留下带拖尾的水墨笔触，并让笔触缓慢淡出。」
点击冲击波「点击时发出一个冲击波圆环，让它经过的画面发生扭曲。」
拍手「检测到响亮的拍手声时，触发一次泼墨爆发。」
步骤
  1. 从上表选 1 种交互（鼠标 / 键盘 / 麦克风 / 滚轮 / 摄像头）。
  2. 用一句自然语言把它描述给 Gemini。
  3. 跑通后自测：你会想「再用一次」吗？
  4. 录一段带交互的 30 秒 演示。
产出
含一种交互的页面 + 30 秒 带交互演示视频。
讨论
  1. 你的交互「用一次就够」还是「想再用一次」？
  2. 交互改变了观众听音乐的方式吗？
  3. 给产品经理看，他会怎么改？
✦
教学点 — 好的交互让人想再做一次。没有这个的交互只是装饰。
练习 4

风格即文化

35 分钟

目标 — 把视觉做成真水墨——渗墨、飞白、留白、泼墨，而不是「灰色几何形」。继续迭代，加入下面至少 3 项。

至少应用以下 3 项处理
将画面改为真正的中国水墨风格，而不是灰色几何形：
1. 画布使用温暖的宣纸米白色（#FAF6F0），带轻微纤维纹理，并保留大量留白。
2. 使用笔触而非几何形：两端收细、宽度变化，湿润边缘柔和渗入纸面，
   通过透明度羽化表现渗墨。
3. 让墨色从深到浅层层晕染，体现「墨分五色」；快速笔触中出现干笔「飞白」纹理。
   只选一种克制的强调色：朱砂红印章，或玉绿色 #5B8C7E。
4. 强节拍出现时触发一次泼墨：墨滴散开，随后在约 1 秒内扩散并干燥在纸上。
5. 低频脉冲应像新墨在湿纸上自然晕开，而不是简单缩放一个圆形。
6. 加入一条浅淡的垂直中轴线（北京中轴线意象），使用中文衬线字体 Noto Serif SC，
   并在角落放置一枚小红印章。
参考视觉：雪舟等杨的《破墨山水图》。
步骤
  1. 继续迭代，套用上方 ≥3 项水墨 / 中国风处理。
  2. 删掉一个 AI 多给、不搭的元素。
  3. 保留完整 提示词日志（所有迭代）。
产出
视觉升级后的页面 + 提示词日志（保留所有迭代历史）。
讨论
  1. 这些视觉元素真的「中国」吗？还是只是符号？
  2. 你删掉了哪个 AI 给的元素？为什么？
  3. 不懂中国文化的观众能感觉到「水墨」吗？
✦
教学点 — 水墨的关键不是「黑白」，而是墨分五色 + 留白 + 笔触动态；印章 / 中轴是点睛，不是堆砌。

常见报错与急救（对照水墨案例）
点了播放没声音浏览器自动播放限制：在点击播放或按下回车的交互事件中创建或恢复 AudioContext；当 state==='suspended' 时调用 resume()。
麦克风／摄像头权限被拒getUserMedia 需要 HTTPS 或 localhost 环境，不能使用 file://；通过 try/catch 捕获失败，并将开关恢复为关闭状态。
createMediaElementSource 报错每个 <audio> 只能创建一次音频源；对 AudioContext 和音频源进行单例保护（if(audioCtx) return）。
掉帧限制圆环与粒子数量，将帧差分析画布缩小为 40×30，复用一个 Uint8Array；在性能较弱的设备上关闭画面抖动与 shadowBlur。
🆘 Gemini 反复给出错误结果时的处理顺序 — 同一问题试 3 次仍失败就换方法，别死磕：① 报错原样粘回 + 返回完整、修正后的 HTML；② 缩小范围 只修改音频部分，其余内容保持完全一致；③ 回滚到上一版能跑的 HTML，再只加一小步；④ 仍不行 → 叫老师 / 换更简单的交互 / 直接参考水墨案例二创。铁律：永远留一份「上一版能跑的 HTML」。
